# DOME Modernization Implementation Plan v1.0

**Date:** 2026-08-10  
**Status:** Approved implementation baseline / controlled execution — reconciled to DIMS-ART-0002 v2.0  
**Institutional source:** Google Drive → DOME → Strategic Objectives  
**Registration:** Pending Canonical Artifact Register authority reconciliation

## Purpose

Convert the completed repository audit, live Supabase audit, historical-lineage audit, Google Drive evidence-gap closure, governing synchronization policy, and current eight-module architecture authority into a controlled modernization program for the DOME application.

The objective is **not** to rebuild DIMS from scratch. The objective is to converge, secure, modernize, and integrate mature DMS/DIMS/DIMS-v3 capabilities into one coherent DOME application under **EBYC — Extend Before You Create**.

## Governing target state

- **DOME:** See & Command
- **Eight Modules:** Work & Operate
- **DI:** Understand & Connect across modules
- **KUBERNĒSIS:** Govern & Orchestrate; not a module
- **Administration/System:** Configure & Govern
- **VAULT/Repositories:** Preserve & Recover

Canonical first-class operational modules: GEGRAPTAI™, NESHAMAH™, TETELESTAI™, OrEl™, YARATHĒKĒ™, SHAMAR™, OIKONOMOS™, EKKLĒSIA™.

Supporting classifications: RUARĒ!™ is a user-triggered on-demand prophetic action inside NESHAMAH, not a module. MARTUREŌ™ is deorbited, not deleted; preserve historical lineage but do not implement it as an active module/function. EKPOREUMA™ is removed from active architecture and retained for historical provenance only. Dominion1st Intelligence™ is a persistent cross-module intelligence layer, not a module. KUBERNĒSIS™ is the governance, steering and orchestration layer, not a module. Discipleship is a major EKKLĒSIA process/workspace, not a ninth module.

## Non-negotiable doctrine

1. EBYC — Extend Before You Create.
2. Convergence Without Erasure.
3. Verification Before Completion.
4. No “Newest File Wins.”
5. Prophetic content remains spiritually/human governed; AI may assist but may not represent generated wording as divine revelation.
6. Security Before Expansion.
7. OrEl creates → TETELESTAI tracks completion where appropriate → YARATHĒKĒ preserves and presents established knowledge.
8. OIKONOMOS owns stewardship/resource records → TETELESTAI owns actions/tasks arising from those records.
9. GEGRAPTAI summarizes authoritative operational information; it does not become the source of truth for module records.

## Phase 0 — Baseline freeze & authority control

Resolve authority conflicts that affect implementation: Canonical Artifact Register duplication, ADR/standard status, Enterprise Asset IDs, Cloudflare/Netlify production roles, and backup/restore confidence. No destructive archive/reorganization before authority and restore confidence are established.

## Phase 1 — Stabilize & Secure — CRITICAL

### 1.1 Supabase security
- Verify backup/restore procedure.
- Remove unconditional public ALL access from `asset_registry`, `peace_safety_briefs`, `projects`, `sync_log`, `tasks`, and `teachings`.
- Establish least-privilege role-based policies.
- Review broad authenticated ALL policies.
- Harden database function search paths.

### 1.2 Reproducible database
- Convert captured baseline into replayable migrations.
- Source-control constraints, indexes, functions, triggers, grants and RLS.
- Add schema drift checking.

### 1.3 OrAI hardening
- Add authentication/authorization, rate limits, quotas, request validation, safe errors, observability and prompt/model versioning.
- Remove misleading offline current-intelligence fallback.
- Disable autonomous AI “Now Word” generation.

### 1.4 Runtime truthfulness and stale schema cleanup
- Compare every frontend table reference to live Supabase.
- Resolve stale references such as `briefings`, `resume_points`, and `system_snapshots` where they no longer match backend reality.
- Replace unsupported operational/live claims with verified state.

### 1.5 Production/archive separation
- Stop publishing repository root.
- Establish dedicated build/output directory.
- Exclude ZIP archives, audits, test pages, historical variants and metadata exports from production output.

**Phase 1 completion gate:** security, database reproducibility, AI governance, schema truthfulness and production/archive separation must all be verified.
