## Audit direction

Codex must compare these as complementary design lineages, not select one merely because it is easier to implement.

Evaluate:

- which circular/orbital versions best express DOME as a command environment;
- which regular-grid designs contain superior operational information architecture;
- what should remain command-level visual orientation versus module-interior workflow UI;
- whether the large HTML prototypes preserve interactions, animation, navigation, or layout logic worth extending;
- whether duplicate filenames/images represent exact copies or meaningful variants;
- how the visual lineage should inform the unified DOME app shell.

## Target interpretation

The governing design doctrine is:

**DOME home / executive experience:** circular or orbital command metaphor.  
**Module interiors:** function-appropriate grids, cards, lists, editors, libraries, timelines, intelligence panels, forms, dashboards, and other layouts.

Do not flatten the app into a generic enterprise grid, and do not force every operational screen into a circular layout.
