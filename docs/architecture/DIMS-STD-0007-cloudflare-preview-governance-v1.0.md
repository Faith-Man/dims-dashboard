# DIMS-STD-0007 — Cloudflare-First DOME Preview Governance v1.0

**Status:** Governed standard
**Effective:** 2026-09-10
**Applies to:** DIMS/DOME application development, repair, modernization, and user acceptance testing

## 1. Governing Rule

DIMS/DOME uses one primary verification path:

**GitHub governed task/branch/PR → Cloudflare Workers branch preview → user verification/sign-off → merge/promotion → Cloudflare production.**

Cloudflare Workers is the canonical DIMS/DOME preview and production environment. A successful Netlify preview does not constitute DOME acceptance unless a task explicitly designates Netlify as its test target.

## 2. One Active Preview per Governed Task/PR

Each active DIMS/DOME implementation task should have one canonical Cloudflare branch-preview alias associated with its governed GitHub branch/PR. That URL is the authoritative user-review URL for the task.

Older branch previews are historical/reference evidence only and must not be represented as the current acceptance environment.

## 3. Netlify Scope

Netlify may remain connected for:
- Dominion1st public-site work where Netlify is the designated deployment platform;
- secondary/fallback diagnostics when explicitly needed;
- historical preview evidence.

Automatic Netlify checks generated by repository integrations do not change the canonical DOME verification path and should not be offered as the primary DOME test URL.

## 4. Production Protection

Production remains untouched until the governed Cloudflare branch preview has passed required acceptance checks and the user explicitly authorizes promotion/merge when required.

Do not invoke the production-only `Deploy DOME` GitHub workflow merely to obtain a test environment. Cloudflare's branch-preview integration is the required preview mechanism.

## 5. Acceptance Link Rule

When presenting a DIMS/DOME test link to the user:
1. confirm the preview corresponds to the current governed branch/PR head commit;
2. confirm the Cloudflare Workers build succeeded;
3. use the Cloudflare branch-preview alias;
4. identify the feature/path being tested;
5. do not substitute a Netlify preview without explicitly stating why.

## 6. Recovery / Historical Sites

Known-good older Cloudflare previews may be used as comparison controls to recover proven implementations. They are not active development targets. Recover the required implementation into the current governed branch rather than continuing development on an obsolete test branch.
