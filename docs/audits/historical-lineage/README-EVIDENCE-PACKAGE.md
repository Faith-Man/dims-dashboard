# Historical Lineage Audit — Evidence Package

**Purpose:** Provide Codex with a read-only, source-grounded evidence layer for the DMS → DIMS → DIMS-v3 → DOME historical audit.

**Governing instructions:** `CODEX-HISTORICAL-LINEAGE-AUDIT-INSTRUCTIONS.md`

## Evidence boundaries

This package mirrors **selected metadata, folder manifests, lineage evidence, and design-prototype references** from Google Drive. It does not claim to be a byte-for-byte copy of every historical folder. Google Drive remains the canonical institutional repository for the underlying artifacts.

Codex must treat this package as an audit aid, not as authority to modify Drive or historical records.

## Included evidence files

- `drive-source-index.md` — source roots, IDs, roles, and authority cautions.
- `dms-lineage-evidence.md` — earliest identifiable DMS baseline and related lineage evidence.
- `dims-lineage-evidence.md` — recovered DIMS launch evidence and backup-copy warning.
- `dims-daily-backups-evidence.md` — top-level preservation repository manifest and role.
- `dims-v3-evidence.md` — current DIMS-v3 root structure and institutionalization evidence.
- `dome-current-evidence.md` — current DOME root structure and present module-development evidence.
- `design-lineage-evidence.md` — circular/orbital, regular-grid, HTML, and recovered design prototype inventory.

## Non-destructive rule

Do not rename, move, delete, overwrite, archive, deploy, commit changes to historical source material, or treat backup copies as canonical merely because they are newer.

## Audit method

Use this evidence together with:

1. current repository code;
2. `docs/architecture/DIMS-ART-0002-dome-seven-module-architecture.md`;
3. `supabase/baseline/2026-08-09/`;
4. the governing audit instruction file;
5. current GitHub implementation evidence.

Where this package says authority is unresolved, report the uncertainty rather than inventing a conclusion.
